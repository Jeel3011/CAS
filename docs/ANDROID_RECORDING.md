# Android Recording Guide — Camera + IMU Dataset Capture

This describes how to capture one run on your Android phone so the laptop pipeline can consume it.

## 1. Recommended apps

Any app that produces **MP4 video + a CSV of accel/gyro with timestamps** will work. Tested options:

| App | What it gives you | Notes |
|---|---|---|
| **Sensor Logger** (Kelvin Choi) — free | video + accel + gyro + magnetometer + per-frame timestamps | Easiest. Export → ZIP. Use this first. |
| **Physics Toolbox Sensor Suite Pro** | high-rate IMU CSV, video separately | Record IMU and video simultaneously, sync by a clap/tap. |
| **SensorStream IMU+** | IMU streamed over UDP | Use only if you want live streaming. |

Install **Sensor Logger** from the Play Store. The rest of this guide assumes it.

## 2. Phone settings (one-time)

1. **Developer options → USB debugging:** ON (needed only for `adb pull`).
2. **Camera resolution:** 1920×1080 at 30 fps. Lock exposure if possible.
3. **Disable auto-rotation** during a run.
4. **Airplane mode ON** (reduces OS noise on sensor timing).

## 3. Per-run capture procedure

1. Open **Sensor Logger** → gear icon → enable:
   - Accelerometer @ 100 Hz
   - Gyroscope @ 100 Hz
   - Video @ 1920×1080, 30 fps
   - Enable "write per-frame timestamps".
2. Stand at the room's start position. Hold the phone in landscape with the rear camera forward.
3. Hit **Record**. Immediately do a **vertical phone tap** (sharp up–down) — this spike makes IMU/video alignment easy.
4. Walk the planned path. Keep the camera roughly level; slow turns.
5. End with another vertical tap, then stop recording.
6. **Export** as ZIP.

## 4. Transfer to laptop

### Option A — USB (MTP)
Plug phone in, open file browser, copy the exported folder to `data/raw/<run_name>/`.

### Option B — ADB (recommended, scriptable)
```bash
adb pull /sdcard/Android/data/com.kelvin.sensorapp/files/Recordings/<folder> data/raw/<run_name>/
```

## 5. Expected layout after transfer

```
data/raw/<run_name>/
├── video.mp4
├── imu.csv            # columns: time_ns, ax, ay, az, gx, gy, gz
├── timestamps.csv     # columns: frame_idx, time_ns
└── meta.yaml          # optional: notes, lighting, path type, markers visible
```

If your app produces different column names, edit `src/acquisition/dataset.py` → `IMU_COLUMNS` to match, or run the normalization helper:
```bash
python -m src.acquisition.normalize_sensor_logger --in <export_folder> --out data/raw/<run_name>
```

## 6. Sanity check

```bash
python -m src.acquisition.dataset --inspect data/raw/<run_name>
```
Should print:
- Video duration and FPS
- Number of IMU samples and mean rate
- IMU/video overlap (≥ 90 % expected)
- Timestamp monotonicity

## 7. Marker setup for the room

- Print `data/markers.pdf` (generated by `scripts/generate_aruco_markers.py`) at 100% scale on A4.
- Mount markers on walls / fixed objects at eye-to-chest height, visible from the planned path.
- Record each marker's `(x, y, z)` **in the world frame** (origin = marker 0) in `data/raw/<run_name>/marker_gt.yaml`:
  ```yaml
  markers:
    0: { x: 0.0, y: 0.0, z: 1.2, yaw_deg:   0 }
    1: { x: 2.1, y: 0.0, z: 1.2, yaw_deg:   0 }
    2: { x: 2.1, y: 3.4, z: 1.2, yaw_deg:  90 }
    # ...
  ```
- Also record 3–5 **trajectory waypoints** on the floor (marked with tape) and their `(x, y)` — these become our ground-truth checkpoints for ATE.
